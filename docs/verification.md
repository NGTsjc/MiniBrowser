# Windows 原生验收

自动化：`pnpm build:debug` 后运行 `pnpm test:smoke`。使用真实 WebView2 和本地测试网页验证便携配置、URL 保持会话、权限拒绝、隐藏暂停、重复启动和会话重建，并保存界面截图与结果到 `.cache/smoke-portable/<时间戳>`。

2026-10-27 本机已通过：前端类型检查／生产构建、Clippy 全目标检查、12 项 Rust 测试，以及真实 WebView2 集成检查。原生探针已验证背景按下即拖动并跟随鼠标位移、左上角零边距、设置弹窗居中、横屏默认尺寸、引导页隐藏滚动条、边缘缩放、工具区透明度联动、七项自绘右键菜单、恢复位置与尺寸、释放后越界回弹、任务栏样式和全局快捷键；已验证音视频暂停与重启新会话。自绘菜单验证包含键盘导航、Esc 关闭、边缘避让、点击操作及设置草稿保留，并保存菜单截图供视觉检查。主题检查包含浅色背景、八种预设色块、白／黑／高饱和色按钮对比度、非法 HEX、Esc 撤销、保存失败保留草稿及重试、恢复默认预览、引导页与菜单同步、重启和会话重建恢复，远程网页不应用主题；配置测试覆盖旧配置与非法主题字段逐字段兜底。边界单元测试覆盖负坐标、相邻显示器、桌面空隙、显示器断开和超大窗口。遇到文件延迟释放时，测试会额外验证下次启动补清理。调试器可能延长 WebView2 的文件占用，测试会在重建前主动断开调试连接。受限文件系统可能报告增量缓存无法硬链接而改为复制，不影响检查结果。

发布版也已通过独立启动检查：x64 GUI 子系统、读取持久化透明度、快捷键隐藏／恢复后透明度与任务栏样式保持、相对 EXE 存储、原生关闭。PE 依赖检查确认不需要旁置 WebView2Loader 或 VC++ 运行时 DLL；仍依赖系统 WebView2 Runtime。

加入页面缩放后，真实 WebView2 集成检查共 36 项通过：本地引导页和拖动区打开应用菜单，远程网页的右键事件未被取消且不会弹出应用菜单，网站自定义菜单可显示，真实鼠标点击跨域 iframe 后其右键事件能执行。原生复制菜单的自动化 UI 识别未通过，因此不作为已验证项目；文字选择／复制／粘贴应在目标环境手动复核。通过拖动区菜单打开开发者工具，原生进程树窗口检查确认其调试目标为测试网页；重复打开仅一个工具窗口，关闭工具后网页仍可浏览。正式构建开启 Tauri `devtools` 功能，本地控制 WebView 单独禁用开发者工具；发布版仍不包含测试 CDP 环境变量入口。

托盘重置验证通过真实 Win32 托盘菜单执行，覆盖四项菜单顺序、显隐文字变化、隐藏且缩放越界的窗口恢复至 960×600 并居中、显示状态重置及悬浮菜单关闭。检查确认页面未重新加载，Cookie／网站存储、已保存偏好、未确认 URL 草稿和透明度预览均保留，重置尺寸写入便携配置。小屏适配沿用现有工作区裁剪，超大窗口与显示器空隙由既有边界单元测试覆盖；多显示器不同缩放及实际小屏仍需按下表人工验收。

新页面集成验证覆盖 `_blank`、Ctrl／中键链接、脚本、命名窗口和跨域 iframe 请求，确认始终只有一个浏览目标且保留 Cookie／网站存储，成功时无设置提示；另验证实际 URL 更新、启动 URL 与编辑草稿保持、iframe 内导航和页面内选项卡不受影响。空白、外部协议、文件、data 和 blob 目标不产生额外页面或当前页导航。单元测试覆盖队列请求在忙碌、退出、会话更换时失效；不以集成测试声称已穷举所有生命周期时序。

圆角验证在 Windows 11（10.0.26200）、150% 缩放下进行：原生区域检测覆盖 0／12／32 半径、主窗口四角与拖动区交集、圆角空白处不命中应用；真实鼠标验证四角缩放（包含拖动区覆盖的左上角），并检查 280×200 最小窗口、设置面板与菜单切换、托盘重置时的预览保持、重启及会话重建恢复。实际窗口截图复核了 canvas.captureStream 视频元素在 100%／20% 不透明度及连续缩放时的裁剪，无黑角；保存失败回退保留草稿、Esc 还原及远程网页无预览权限也已验证。采用 GDI 区域裁剪，复用固定版本 Tauri 的原生缩放边缘，缓存形状并处理 WM_SIZE 重建；不使用全局鼠标钩子。Windows 10、其他 DPI／多显示器以及各类硬件解码播放器仍需在相应环境人工复核。

缩放验证使用 Win32 键盘／鼠标输入，覆盖 Ctrl＋滚轮向上／向下／连续刻度、Ctrl＋加减号、Ctrl＋0、普通滚动、跨域 iframe 和非 passive 的网站滚轮监听；检查刷新、同来源导航、不同来源独立比例和新页面转入当前窗口。设置／菜单禁用缩放，确认／取消设置、隐藏／显示、托盘重置后比例保持，窗口位置、尺寸、透明度与圆角区域不变；清空会话和重启后恢复 100%。结果见 `.cache/smoke-portable/1793114601761/report.json`。测试采用模拟滚轮输入，物理鼠标、精密触控板、不同键盘布局与其他系统版本仍需人工复核。

实现与最初方案有一项调整：实测 WebView2 用户缩放在导航后复位（亦见 [WebView2 官方反馈 #2451](https://github.com/MicrosoftEdge/WebView2Feedback/issues/2451)），因此不能仅开启快捷键来获得网站记忆。新增控制器生命周期内的来源→比例内存表，用原生接口在导航后恢复，并在 Ctrl＋0 时恢复 100%；按协议、主机、有效端口分别记录，不合并域名。导航自身的复位不覆盖用户记录，旧会话的排队恢复不作用于新会话；不持久化、不新增配置或远程 IPC，不注入缩放脚本。

发布前还应在目标机器检查以下原生集成场景：

| 场景 | 预期 |
| --- | --- |
| 双屏分别使用 100%、150%、200% 缩放 | 在鼠标所在屏幕工作区居中，拖动区和弹窗尺寸、位置正确 |
| 菜单打开设置、按住拖动区 | 菜单设置项打开居中弹窗，已打开时保留草稿；左上角仅保留拖动区，按下立即跟随鼠标 |
| 拖动四边、四角 | 缩放正常，无可见原生边框，无网页点击误触 |
| 设置面板缩到最小尺寸 | 可滚动，取消／确认仍可操作 |
| 圆角 0／12／32、透明度 20%／100%、视频及最小窗口 | 网页和拖动区同步裁剪，无黑角或方形背景；四角可缩放，裁掉的角落不截获鼠标；确认保存、取消还原 |
| 主题色预览、确认、取消、重启 | 浅色背景不变，面板内预览；确认统一保存，取消恢复，重启保留；白色／黑色强调色仍可操作 |
| 调节不透明度，播放视频并滚动 | 整个网页透明，浮层清晰，没有黑屏和异常闪烁 |
| 确认／取消不透明度、隐藏再显示 | 拖动区保持与网页相同的不透明度，设置弹窗不受影响 |
| 引导页／拖动区右键 | 七项应用菜单顺序正确；方向键选择、Enter 执行、Esc 和点击外部关闭；设置草稿保留 |
| 远程网页和 iframe 右键 | 保留文字编辑／复制等 WebView2 菜单及网站自定义事件，不弹出应用菜单 |
| 菜单开发者工具 | 打开当前网页的独立调试窗口，重复点击只保留一个；关闭后网页继续浏览，应用设置界面不开放开发者工具 |
| 拖到屏幕外、跨显示器、任务栏附近 | 拖动中不强行改变位置，松开后回到真实显示器工作区；相邻屏幕之间允许跨屏，空隙不算桌面 |
| 隐藏／恢复、快捷键长按 | 托盘菜单随状态变化，每次按键只切换一次，不自动恢复媒体 |
| 托盘重置窗口 | 菜单顺序为显隐、重置窗口、关闭、重启；隐藏或越界后重置会显示并居中，恢复默认尺寸并保存，保留网页会话、应用设置及未确认草稿 |
| 另一应用占用快捷键 | 明确提示，保留旧绑定；托盘仍能恢复 |
| 新标签页、脚本窗口与 iframe 弹出 | HTTP／HTTPS 目标进入当前窗口，无额外浏览窗口，登录状态保持；独立登录弹窗和 POST 新窗口表单不作为支持场景 |
| 页面 Ctrl＋滚轮、Ctrl＋加减号／0、浏览器返回 | 页面缩放，同来源刷新／返回沿用比例，不同来源独立；Ctrl＋0 为 100%；应用浮层与窗口尺寸不变 |
| 缩放后隐藏／托盘重置／清空会话／重启 | 隐藏和重置保留比例，清空会话和重启恢复默认；物理鼠标及精密触控板分别检查 |
| 托盘重启、连续快速双击 | 仅一个实例，加载已确认地址，不复用浏览数据 |
| EXE 所在目录只读 | 原生错误提示，不回退写入 AppData |
| 手动损坏配置，再启动、缩放、退出 | 使用默认值，原损坏文件保留；确认设置后才替换 |
| 强制结束程序后再启动 | 清理失效会话目录，不恢复 Cookie；设置仍存在 |
| 缺少／过旧 WebView2 的干净机器 | 提示运行环境要求，不自动下载或安装 |
| Process Monitor 按进程树筛选文件写入 | 应用配置、UI 和网页数据位于 EXE 同级数据目录；区分系统运行环境自身写入 |

不要以 DOM 截图替代原生透明度和窗口层级验收；截图只能验证网页布局。干净系统环境、多显示器与全量文件访问追踪需在相应环境下复核。
